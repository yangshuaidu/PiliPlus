# 直播间互动与消息

本分支沿用原有播放器、弹幕输入、聊天／SC 页面、屏蔽管理和观众榜，在这些入口中扩展互动功能。没有新增账号系统，也不会自动送礼、付费、发送弹幕、关注或参与抽奖。

## 功能与入口

| 入口 | 行为 |
| --- | --- |
| 礼物 | 官方分类独立展示、价格排序、包裹、电池余额和官方充值入口；普通电池礼物及背包赠送 |
| 礼物中的红包 | 原生礼物／上舰／电池红包套餐、开奖时间、数量、参与条件、附带弹幕、记录及规则；红包不会作为普通礼物提交 |
| 顶部观众头像和人数 | 复用原观众榜：在线／日／周／月榜；同一面板切换大航海周／月／陪伴榜、上期榜首、自己的排名和官方上舰入口 |
| 红包与天选 | 活动条件、倒计时、手动确认免费参与、开奖结果；小屏放在“更多”菜单，宽屏提供直接入口 |
| 播放器工具栏／更多 → 弹幕设置 | 画面弹幕开关、字体与显示设置、榜单／等级／头衔、表情弹幕、右下角表情、抽奖弹幕及 SC；保留平台屏蔽词／用户管理入口 |
| 播放器工具栏／更多 → 礼物设置 | 赠礼消息、上舰提示和礼物特效分别开关；关闭消息不再连带关闭特效 |
| 播放器工具栏／更多 → 通知设置 | 进场、关注、分享、红包／天选、全站广播、直播间广播、点赞、榜单、开播／房间变更、房间警告和其他系统通知分别开关；仅控制直播间内提示，不是系统推送 |
| 更多 → 播放设置 → 后台听直播／全局播放器设置 → 直播后台播放 | iOS、Android 共用独立直播开关，默认开启；与普通视频后台播放设置分开保存 |
| 原弹幕输入面板 | 滚动／底部／顶部位置、官方颜色分组与账号锁定状态；非默认样式发送前重新核验权限；SC 购买入口 |
| 原 SC 页面 | 保留查看能力并增加原生购买：服务器档位、自定义金额、中译日、已有定制动画素材、附加费用、账号和费用二次确认、订单留言查询 |
| 视频画面 | PK 双方分数、阶段和倒计时；点击成员显示主播及房间资料和已有关注／跳转能力；礼物 GIF／WebP、官方允许在播放器展示的表情 |
| 聊天区 | 榜单、荣耀等级、头衔、大航海、勋章、房管；自己和他人的赠礼、进场、关注及系统消息；连接状态、手动重连及本人弹幕回显状态 |

移动端与桌面共用 Flutter 控件。面板限制最大宽度、正文可滚动，输入面板避让键盘；观众／大航海合并入口，减少顶部拥挤。观众榜显示接口提供的本人名次；长昵称单行省略，榜单行高随内容变化。大航海在短屏或大字体下整体滚动，保留本人排名和上舰入口；切榜失败后从第一页重试。后续分页未重复返回本人信息时保留已有排名，首屏刷新则以新结果为准。礼物分类不换成多行；窄屏仍可滚动选择。礼物和表情视频叠加排除画中画。

## 移动观看与资料面板

- 分区观看的视频左右铺满、无卡片圆角；竖屏视频默认叠加布局，也可从“更多”手动切换竖屏全屏／分区观看。清屏隐藏顶部资料、聊天和输入区，保留退出清屏按钮。
- 播放器底栏保留播放、清晰度、全屏和更多；分享、刷新及分类工具收进底部图标菜单。后台播放、比例、线路、定时关闭及播放信息位于播放设置。
- 未开播、已结束及播放地址错误显示在视频区域，可手动刷新，不弹出阻断观看的对话框。
- 聊天正文使用 15 逻辑像素、1.4 行高、消息间距 4；徽章与昵称同行。表情按逻辑尺寸显示，不再用设备像素密度缩小。输入区采用胶囊输入框和圆形按钮。
- 点击弹幕昵称或身份徽章打开用户资料；点击正文打开回复、举报、屏蔽菜单。资料包含接口提供的关注数、粉丝数、荣耀等级、粉丝勋章和当前头衔，并保留更多、私信、回复和关注。勋章主播信息及头衔条件未返回时明确显示缺失，不编造头衔清单或消费金额。
- 礼物、红包、SC、资料和设置使用统一半屏容器，非提交期间可点击外部关闭。锁定礼物可查看限制原因，赠送按钮禁用；选中锁定礼物不会继续赠送之前选择的礼物。
- 红包刷新会清除上一次错误与旧选择。平台 `can`、`tips` 和配置数量范围仍被保留；修复界面错误残留不表示已解除账号或平台的红包数量限制。
- iPhone 17 布局验证采用 402×874 逻辑尺寸、3 倍像素比例；顶底安全区由运行时读取，不按机型硬编码。测试中的安全区仅为覆盖样例。

## 设置保存与即时生效

- 弹幕、礼物、通知均有直接入口；面板中以分段控件切换三个分类，正文滚动、标题与关闭按钮固定。竖屏礼物及分类设置面板通常占可用高度的 48%，最高 420；横屏在右侧显示，保留至少一半横向空间。键盘或极短屏下优先保证面板可操作。
- 礼物默认展示官方房间列表，粉丝团、航海等分类只展示各自的 gift ID，不再把全部分类合并到默认页；同一分类重复 ID 去重，不按同名去重不同 ID。礼物四列布局，大字体改为三列，余额与操作位于底部。
- `LiveRoomSettings` 是分类显示设置的唯一所有者，所有打开的直播间共享。切换立即影响已显示消息和后续消息；连续保存按顺序执行，磁盘保存失败时恢复上次保存值并显示错误。
- 旧版 `liveMessageFiltersV1` 自动迁移到 `liveRoomSettingsV2`，保留原屏蔽效果。之后礼物消息、特效、广播以及抽奖弹幕、活动通知可以独立调整；不因升级重新展示原本屏蔽的类别。
- 关闭礼物特效会清空队列并使尚未完成的素材加载失效；重新打开后新礼物可以正常展示。关闭 SC 会清除对应卡片，重新开启时重新获取仍有效的留言。
- “恢复本页分类默认值”只重置当前分类，不改变其他分类、发送样式、平台屏蔽规则或购买记录。
- 画面弹幕开关沿用播放器的保存键；开启临时播放器配置时仅本次生效。字号、速度、透明度等沿用原播放器设置并在关闭其设置面板时保存，与视频播放器共用。
- 全局播放器设置将 SC 设为“不显示”时，直播弹幕设置明确显示禁用原因，不显示可用但无效果的开关；改变全局 SC 模式后重新进入直播间生效。
- 系统通知不再作为所有通知的总开关。全站广播与直播间广播依据 `NOTICE_MSG.real_roomid` 区分，上舰提示属于礼物设置；未知通知内容不按文本关键词猜测类别。新增开关继承旧合并开关的屏蔽状态，已有明确的新开关值优先。

## 移动端后台播放

直播与普通视频此前共享默认关闭的后台播放开关，iOS、Android 进入 `paused` 都可能主动暂停。直播现使用独立开关；开启时不因进入后台主动暂停，Android 画中画沿用原有播放行为。只有前台 `resumed` 才能恢复由生命周期策略暂停的播放；`inactive`／`hidden` 不触发恢复，用户或音频中断导致的暂停取消自动恢复。

音频会话激活前等待初始化与配置完成。iOS 已有 `UIBackgroundModes=audio` 与 playback 音频类别；Android 已有媒体播放前台服务和相关权限。应用原有后台服务总开关仍保留。依据：[Apple playback 音频类别](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/playback)、[Android 后台媒体播放](https://developer.android.com/media/media3/session/background-playback)。锁屏、系统音频打断及厂商省电限制仍需手机实测，云端生命周期用例不等于真机音频验收。

## 消息可靠性与隐私

- WebSocket 检查完整包头、遍历同一帧的多包、解开 zlib／Brotli 后继续逐包处理，心跳或单条坏消息不丢掉同帧后续消息。每个监听器的异常独立处理。
- 会话按房间及账号分代，丢弃迟到的令牌、连接和事件；断线有限退避重连，失败后保留手动重试入口。只有稳定连接才重置重试预算。
- 同时解析旧 `DANMU_MSG.info`、二进制 `dm_v2`、赠礼和新版 protobuf 多礼物广播；徽章损坏不丢弃可读正文。赠礼按回执去重，累计连击广播不重复计礼物。
- 抽奖分类使用官方 `biz_scene`／旧协议位置中的场景 1、2，并补充当前活动的精确附带弹幕匹配；不按普通文本关键词猜测抽奖消息。
- 本人发送追踪区分接口接受、当前连接收到回显、暂未收到、明确拒绝和结果未知。同一事件 ID 不会确认两条重复发送。没有回显不能证明被屏蔽；本机收到回显也不能证明所有其他观众可见。
- 遵守明确的匿名标记，隐藏真实 UID、原始姓名、头像和身份装饰，不解析或展示风险控制／原身份字段。观众人数与榜单人数的差值不是隐身人数；不跨接口还原隐身身份。
- SC 使用原消息卡片，兼容新旧用户资料；匿名 SC 不显示原始资料，删除事件移除对应展示。

## 支付与参与约束

普通礼物、红包、SC 和活动共享账号写入互斥；付费交易共用原礼物持久化记录和未知结果核对机制。

- 操作绑定具体登录对象。账号变化、面板关闭或确认超时后不得提交旧确认。付费确认有效期 60 秒，免费活动确认 30 秒。
- 付款确认列出账号 UID、主播、房间、套餐／留言、数量、时长、参与条件及总费用；红包附带弹幕和可能由平台执行的天选关注／弹幕行为必须明示。
- 提交前重新读取价格、权限、库存／余额及活动条件；不信任已显示的缓存价。
- 普通 gift 金额、红包金额和 SC `pay_gold` 使用原始整数 gold。只在显示时按 100 gold = 1 电池换算。SC 配置的 `price` 按官方客户端乘 1000；自定义金额要求 10 电池整数倍。定制动画附加费读取 `customize_dm.amount`。
- 写入 transport 移除自动重试和日志拦截器、禁止重定向，并设置发送／读取超时。一次确认最多一次 POST。持久化提交中记录成功后才允许 POST，记录不保存 Cookie、CSRF 或留言原文。
- 普通礼物匹配礼物回执；红包检查有效活动编号及可用的房间／发送者字段；SC 检查订单编号和状态，分别说明派发、待派发、审核。超时、缺失回执、未确认支付状态或记录落盘失败均保留待核对结果，不自动重发。
- 未知记录跨关闭／重启保留。明确“已核对官方记录”仅解除限制，不重发也不把未知结果改成成功。
- 原生抽奖仅提交已核对协议的免费参与，不包含礼物参数或代付。付费／任务型天选提供官方页面。
- 官方充值和上舰使用浏览器；网页实际登录账号由用户在网页确认。

## 当前边界

- 礼物动态展示支持官方 GIF／WebP，小型队列有界；不含大型 SVGA／MP4 特效、礼物音效及其完整官方编排。
- 头衔使用平台提供的名称／图片；仅有 CSS 标识时显示中性“头衔”，不伪造官方美术。
- 定制 SC 从平台已有素材中选择，不包含本地素材上传、删除和排序。
- 服务端未提供的观众、PK 对手资料或隐私信息不补造。平台权限、风控、地区或账号限制仍由平台决定。
- 不保证复刻官方客户端的所有活动，且不包含自动抢红包／自动天选。

## 验证与验收边界

开发验收使用 GitHub Actions 安装的 Flutter 3.47.6 和项目要求的补丁，不依赖开发电脑的 Flutter 或 Android SDK。Android、Windows 和 iOS 工作流共用 `tool/check_live.ps1`，包含静态检查及 16 个测试文件，覆盖原有账号删除、直播标记、礼物、红包／天选、SC、拆包／重连／回显、匿名字段、徽章、PK、设置保存、窄屏面板、分类隔离、用户资料和移动端后台生命周期。`build.yml` 的 `check_only` 模式仅运行云端检查，不生成应用安装包。

UI 用例覆盖 320／360 像素竖屏、740×360 横屏、键盘避让，以及 Android／iOS／Windows 主题下 SC 确认与取消不提交；榜单另覆盖 320×240 短屏、双倍字号、匿名身份和切榜响应乱序。交易用例全部使用假接口，不产生真实礼物、SC 订单、弹幕或抽奖参与。

移动布局回归额外覆盖 393×852、360×640 礼物面板与全站广播开关；截图使用标明“布局回归样例”的模拟直播页，并检查面板不覆盖该竖屏样例的视频区域。截图不是实际账号直播画面的记录。

设置用例覆盖真实 Hive 文件关闭／重开、旧配置迁移、错误类型、快速写入顺序、保存失败恢复、分类独立性、分类默认值恢复、全局 SC 禁用提示、三个平台主题下关闭／重新打开，以及三类设置在 320×240 短屏和双倍字号下的实际开关操作。

以同一提交的 GitHub Actions 测试、静态检查、Windows 原生打包及 Android APK 构建记录为验收依据。构建成功与平台主题测试均不是手机真机运行证据。Android 沿用仓库签名设置；未配置发布签名密钥时使用调试证书，不能保证覆盖安装其他证书签名的已有应用。未使用真实账号执行扣费或抽奖参与，真实账户配置、回执、余额变化及各端真机显示仍需实际验收。

iOS 沿用仓库的 `flutter build ios --release --no-codesign` 流程生成 IPA，框架做临时签名以兼容后续签名工具。它不是 App Store／TestFlight 发布包；安装到 iPhone 仍需用户的签名或侧载流程。只有对应 Actions 任务实际成功后，才将该次 IPA 作为已完成构建交付。

项目 `.gitignore` 的 `test*` 规则不作全局修改；本分支明确纳入新增测试和假接口文件。
